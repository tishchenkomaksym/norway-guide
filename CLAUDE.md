# nordguide — офлайн-гид по Норвегии

Мобильное приложение (iOS + Android), полностью работающее без интернета: карта Норвегии,
города, достопримечательности с описаниями и фото, готовые маршруты. Контент скачивается
один раз пакетами по регионам.

**Спецификация — источник правды:** `docs/norway-offline-guide-spec.md`
Корень репозитория одновременно является Obsidian-хранилищем, поэтому спека и заметки
редактируются в Obsidian и версионируются вместе с кодом.
Перед нетривиальной задачей сверяйся со спекой — в ней уже приняты решения по стеку,
модели данных, языкам и лицензиям. Не переизобретай их.

## Стек

| Часть | Технология |
|---|---|
| Приложение | Flutter (Dart) |
| Карта | MapLibre GL + PMTiles (локальный файл) |
| БД контента | SQLite + FTS5, доступ через drift |
| Пайплайн данных | Go (`paulmach/osm`, Planetiler) |
| Раздача | статический хостинг / S3, без бэкенда |

Разделение: **Go генерирует контент, Flutter его показывает.** Серверной части нет и не планируется.

## Структура

```
pipeline/        Go: extract → enrich → media → translate → build
  cmd/           точки входа по этапам пайплайна
  internal/      osm, wiki, imageproc, packer
  data/          .pbf и промежуточные файлы (в .gitignore, не коммитить)
app/             Flutter, feature-first
  lib/core/      di, темы, роутинг
  lib/data/      drift-схема, репозитории, менеджер загрузок
  lib/features/  map, cities, place, routes, favorites, downloads
  lib/l10n/      en, no, de, es, ru, zh
docs/            спецификация и производные заметки
.obsidian/       настройки хранилища (корень проекта = vault)
```

## Правила, нарушение которых ломает проект

**Интерактивной карты в MVP нет. Основной экран — «рядом со мной».**
Тайлы, стили, глифы и кластеризация — самая дорогая подсистема проекта, и она не нужна,
чтобы закрыть главный сценарий «я стою здесь, что вокруг». GPS работает без сети всегда,
координаты всех POI лежат в базе, поэтому список ближайших мест с расстоянием и
направлением («Vøringsfossen — 4.2 км, на северо-восток») работает офлайн, без трафика
и без единого мегабайта тайлов.

Как устроена географическая часть:

| Что | Как | Офлайн |
|---|---|---|
| Главный экран | Список «рядом со мной» по GPS, сортировка по расстоянию, фильтр категорий | да |
| Города и места | Списки, карточки, фото, описания | да |
| «Где это» в карточке | Статичное превью карты, только для топ-1000 объектов | да |
| Навигация | Кнопка «открыть в Google / Apple Maps» (`geo:`, `maps://`) | нет, и это нормально |
| Интерактивная карта | Отдельная функция после релиза, скачивается по кнопке | после скачивания |

Правила:
- Превью генерируются заранее в пайплайне, растр WebP, только для топ-1000 по
  `importance` и для городов: 15 000 превью весили бы ~600 МБ, что тяжелее векторных
  тайлов. Объектам без превью карточка показывается без картинки — это не ошибка.
- Расстояние и направление считаются локально, без сети. Пересчёт по движению GPS
  троттлить, иначе список будет дёргаться и жрать батарею.
- Кнопка внешней навигации есть у каждого места; при отсутствии сети она честно говорит,
  что нужен интернет, а координаты остаются доступны для копирования.
- Когда интерактивная карта появится: спрайты и шрифтовые глифы MapLibre обязаны лежать
  в assets, иначе скачанный регион окажется картой без подписей — самая частая ошибка
  в офлайн-картах.

Изображения и тексты подчиняются той же модели (см. ниже про три уровня).

**Карта статична и не обновляется сама.**
Это не Google Maps: данные пересобираются раз в 1–3 месяца и версионируются. Скачанный
регион живёт, пока пользователь сам не обновит его.

- Никаких фоновых обновлений, никакой докачки тайлов без явного действия пользователя.
- Скачанный регион не перекачивается при выходе новой версии. Приложение показывает
  ненавязчивую пометку «доступна версия от <дата>» в экране загрузок — и всё.
- Кэш сетевых тайлов не имеет короткого TTL: тайл, скачанный месяц назад, остаётся
  валидным. Инвалидация — только при явном обновлении региона пользователем.
- Достопримечательности, фьорды и музеи не меняются от недели к неделе. Меняются часы
  работы и цены — это текст в БД, а не тайлы, и обновляется вместе с пакетом контента.

Практическое следствие: приложение не должно расходовать трафик и батарею в поездке.
Открыл карту — увидел то, что уже есть, без единого лишнего запроса.

**Тексты живут только в `translations`.**
В `places`/`cities`/`regions` остаётся `name_no` как канонический ключ. Колонки вида
`name_en`, `description_ru` не добавлять никогда. Fallback-цепочка строго:
`язык пользователя → en → no → name_no`, через COALESCE, с флагом `is_fallback`.
Пустой экран пользователю не показывается.

**Лицензии — блокирующее требование, не формальность.**
Фото из Wikimedia Commons только CC0 / CC BY / CC BY-SA; поля `author`, `license`,
`source_url` обязательны. NonCommercial, ND и fair use отбрасывать. Тексты Wikivoyage и
Wikipedia — CC BY-SA 4.0 с атрибуцией. Visit Norway, Lonely Planet, TripAdvisor не парсить.
Экран атрибуции обязателен в MVP.

**Контент сжат и подгружается поэтапно.**
Три уровня гранулярности, а не один монолитный пакет:
1. *Всегда офлайн* (в бандле): все POI, координаты, категории, короткие `summary` на `en`+`no`,
   обзорные тайлы. Пользователь всегда видит карту, список и превью карточки.
2. *По клику, при наличии сети*: полное `description`, фотогалерея места, детальные тайлы
   вокруг точки. Скачанное сразу оседает в постоянном кэше — второй клик уже офлайн.
3. *Предзагрузка региона*: кнопка «скачать перед поездкой», качает уровень 2 целиком.

Ленивая догрузка НЕ отменяет региональные пакеты и НЕ является заменой офлайну: без сети
клик обязан открывать карточку с тем, что есть на уровне 1, и честно помечать, что фото
и полный текст ещё не скачаны. Пустой экран и спиннер без таймаута запрещены.

Тексты хранятся сжатыми (zstd со словарём, общим на язык) — на 15 000 описаний это кратная
экономия против plain text. Распаковка на лету при чтении карточки.

**Бюджеты объёма.**
Бандл в сторе ~40–60 МБ: код, шрифты, стартовая БД с POI и короткими `summary` на
`en`+`no`, превью топ-мест. Тайлов в бандле нет — интерактивной карты в MVP нет.
Региональные пакеты 150–400 МБ (фото и полные тексты), скачиваются по кнопке.
После пересборки базы сообщать фактический размер в МБ, а не оценку.

Замер от 2026-09-09: тайлы Protomaps z0–12, обрезанные по границе Норвегии, весят
**472 МБ** — против ~180 МБ в оценке §5 спеки. Одна из причин, по которой интерактивная
карта вынесена за пределы MVP.

**Раздача — Cloudflare R2, не S3.**
У R2 нулевая плата за egress, у S3 она станет основной статьёй расходов при росте.
Хостинг статический, бэкенда нет.

**Пользовательские данные отдельно.**
`favorites` живёт в отдельном файле БД. Обновление контентного пакета не должно
стирать избранное и заметки пользователя.

**Профиль пользователя ранжирует, но не скрывает.**
Анкеты перед первым экраном нет: приложение открывается сразу на карте с POI,
отсортированными по `importance`. Вопрос о профиле показываем позже, по сигналу
заинтересованности (3 открытых карточки, второй запуск, добавление в избранное или
тап по «скачать регион»), один раз, в bottom sheet поверх карты — что интересно
(мультивыбор: природа, походы, рыбалка, музеи, фото, с детьми, автопутешествие, зима,
круиз) и когда едете. Профиль меняет порядок выдачи и состав подборок через веса поверх
`importance`, но полный каталог всегда доступен через поиск и фильтры карты. Скрывать
категорию можно только по явному выбору пользователя и с возвратом в один тап.
Профиль хранится локально и никуда не отправляется. Детали — `docs/onboarding-profiles.md`.

**Выбор языка при первом запуске.**
Приложение стартует на языке системы телефона, если он есть в списке поддерживаемых
(`en`, `no`, `de`, `es`, `ru`, `zh`); иначе — английский. Экран выбора языка на онбординге
не показываем: язык определяется сам, сменить его можно в настройках.
Соответствие делать по коду языка без региона: `de-AT` → `de`, `zh-Hans-CN` → `zh`,
`nb`/`nn`/`no` → `no`. Выбранный вручную язык запоминается и имеет приоритет над системным.
Язык контента следует языку интерфейса, но при отсутствии перевода работает
fallback-цепочка (см. ниже) — интерфейс при этом остаётся на выбранном языке.

**Локализация: два разных уровня.**
UI (~300 строк) — сразу на все шесть языков. Контент (~15 000 текстов) — по очереди:
`en`+`no` → `de` → `es`+`ru` → `zh`. Машинный перевод помечать `source='mt'`, `quality < 50`.
Шведский, датский и нидерландский не добавлять — решение принято осознанно.
Верстать без фиксированных ширин: `de` длиннее `en` на ~30%, `zh` короче на ~40%.

## Субагенты

Определены в `.claude/agents/`. Границы намеренно жёсткие:

- `sqlite-schema` — **единственный владелец схемы БД**, все правки таблиц через него
- `osm-pipeline`, `wiki-enricher` — Go-пайплайн (извлечение / обогащение)
- `maplibre-offline` — тайлы и рендер карты; не трогает контент
- `flutter-app` — экраны и состояние; не трогает тайлы
- `region-packager` — пакеты, manifest, докачка
- `l10n-content` — переводы UI и контента
- `license-auditor` — read-only аудит перед сборкой пакета и релизом

## Стиль работы

- Отчитываться числами: сколько объектов обработано, сколько МБ весит, сколько отброшено.
  «Готово» без цифр не считается результатом.
- Прогоны пайплайна идемпотентны и перезапускаемы с середины — повторный запуск не должен
  заново качать гигабайты.
- Сетевые обращения к Wikidata/Commons — через общий rate limiter и дисковый кэш.
- Перед сдачей Flutter-кода: `flutter analyze` чисто, тесты зелёные, экран проверен
  в тёмной теме и на локали `de`.
