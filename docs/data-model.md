# Модель данных

Схема повторяет §4 [[norway-offline-guide-spec|спецификации]]. Реализация —
`app/lib/data/tables.dart`, запросы — `app/lib/data/database.dart`.
Владелец схемы — агент `sqlite-schema`; изменения таблиц идут только через него.

## Инвариант, который нельзя нарушать

**Все тексты живут в `translations`.** В `places`, `cities` и `regions`
остаётся только `name_no` как канонический ключ. Колонок вида `name_en`
или `description_ru` быть не должно ни при каких обстоятельствах.

Причина: языков шесть и их число может измениться, а тексты приходят из разных
источников с разным качеством. Колонка на язык означала бы миграцию схемы
на каждый новый язык и невозможность пометить машинный перевод.

## Таблицы

| Таблица | Назначение |
|---|---|
| `regions` | Регионы страны, границы пакетов |
| `cities` | Города, население, заглавное фото |
| `places` | Достопримечательности, координаты, категория, значимость |
| `place_tags` | Мультитеги поверх категории |
| `photos` | Изображения с обязательными автором и лицензией |
| `routes`, `route_stops` | Готовые маршруты |
| `translations` | Все тексты на всех языках |
| `favorites` | Пользовательское: избранное, заметки, «посетил» |

### places

Идентификатор канонический, вида `osm:node/123456` — чтобы объект оставался
узнаваемым между пересборками данных.

`importance` (0..100) — базис сортировки и приоритет офлайн-загрузки.
`season` (`jun-sep`) отмечает объекты, недоступные зимой: горные дороги
закрыты с октября по май, и это единственное, что отделяет полезную подсказку
от отправки человека к закрытому шлагбауму.

### place_tags — добавлено сверх спеки

Мультитеги: `unesco`, `kids_friendly`, `near_port`, `fishing`, `winter_open`,
`wheelchair`. Одной категории для [[onboarding-profiles|профилей]] мало —
«музей с детьми» и «музей для ценителя» это разные объекты одной категории.

### photos — лицензия обязательна

`author`, `license`, `source_url` объявлены `NOT NULL`. Фото без них не имеет
права попасть в базу: это требование §7 спеки, и нарушение блокирует релиз,
а не «ухудшает качество». Проверяется агентом `license-auditor`.

### translations

Ключ — тройка `(entity_type, entity_id, lang)`. Поля:

- `summary` — короткий самостоятельный текст на 2–3 предложения. Именно он
  лежит в офлайн-уровне и часто оказывается единственным, что человек увидит
  без сети. **Не обрезанное начало статьи.**
- `description` — полный текст карточки, догружается по клику.
- `source` — `wikivoyage` | `wikipedia` | `manual` | `mt`.
- `quality` (0..100) — машинный перевод держим ниже 50, чтобы позже заменить
  человеческим без пересборки базы.

## Цепочка подстановки языков

§8.4 спеки: `язык пользователя → en → no → name_no`. Реализована через
`COALESCE` с флагом `is_fallback`, по которому интерфейс показывает честную
пометку «описание доступно только на другом языке».

```sql
SELECT COALESCE(t_user.name, t_en.name, p.name_no)          AS res_name,
       COALESCE(t_user.summary, t_en.summary, t_no.summary) AS res_summary,
       CASE WHEN t_user.summary IS NULL THEN 1 ELSE 0 END   AS is_fallback
FROM places p
LEFT JOIN translations t_user ON … AND t_user.lang = ?
LEFT JOIN translations t_en   ON … AND t_en.lang   = 'en'
LEFT JOIN translations t_no   ON … AND t_no.lang   = 'no'
```

## Поиск по расстоянию

SQL отбирает по bbox, расстояние и азимут считаются в Dart
([[decisions#Расстояние считается в Dart, а не в SQL]]).

При построении bbox учитывается косинус широты: на 71° градус долготы втрое
короче экваториального, и без поправки поиск на севере шёл бы по втрое узкой
полосе.

## Полнотекстовый поиск

`search_fts` (FTS5) — одна строка на пару «объект, язык». В схеме есть,
экран поиска не написан.

Два решения зафиксированы заранее:

- **Искать по языку пользователя И по `no` И по `en` одновременно.** Немец
  видит на указателе «Trolltunga», а не немецкое название; ограничение
  выдачи локалью ломает самый частый сценарий.
- **Для китайского — биграммы, а не ICU.** `sqlite3_flutter_libs` собирает
  SQLite без ICU, и `tokenize='icu zh'` на устройстве просто не создастся.
  Пайплайн разбивает китайские строки на перекрывающиеся биграммы, запрос
  биграммизируется тем же кодом. Тогда достаточно `unicode61`.
