# Архитектура приложения

Как устроен Flutter-клиент. Схема базы — в [[data-model]], подготовка данных —
в [[pipeline-plan]], причины решений — в [[decisions]].

## Общая форма

Приложение почти целиком **read-only поверх локального SQLite**. Мутируемого
состояния мало: избранное, заметки, фильтры, профиль, выбранный язык. Всё
остальное — параметризованные запросы к базе.

Из этого следует выбор инструментов: экран здесь это функция
`(id, язык, фильтры) → запрос`, что ложится на family-провайдеры Riverpod
без событий и состояний в стиле Bloc.

```
Виджет → Riverpod-провайдер → AppDatabase (drift) → SQLite
```

Сети в этой цепочке нет вообще. Единственные сетевые обращения в готовом
продукте — скачивание пакетов контента и открытие внешних карт.

## Структура каталогов

```
app/lib/
├── main.dart              точка входа, темы, локали
├── core/
│   ├── providers.dart     БД, язык, положение, фильтры, выдача
│   ├── profile.dart       интересы, веса, триггер вопроса
│   └── known_places.dart  справочник городов для ручного ввода
├── data/
│   ├── tables.dart        схема drift
│   ├── database.dart      запросы, гаверсинус, азимут
│   ├── connection*.dart   платформенные подключения
│   └── seed_data.dart     тестовые данные Этапа 1
└── features/
    ├── home/              стартовый экран и заставка
    ├── nearby/            «Рядом со мной», выбор города
    ├── cities/            города и места города
    ├── place/             карточка места
    └── profile/           вопрос об интересах
```

## Экраны

### Стартовый

Заставка с фьордом и два пути: [[#Рядом со мной]] и «Города». Второй нужен
там, где первый бесполезен: человек ещё дома и планирует поездку.

Фон нарисован кодом (`CustomPainter`), а не фотографией. Причина не в весе:
снимки обязаны нести автора и лицензию (§7 спеки), и класть чужое фото в бандл
«временно» нельзя.

### Рядом со мной

Заменяет интерактивную карту ([[decisions#Карта вне MVP]]). Показывает
ближайшие места с расстоянием и стороной света. Работает офлайн полностью.

Положение берётся в порядке: указанный вручную город → GPS → центр страны
с большим радиусом. Последний вариант оставляет экран полезным, когда
положение неизвестно, но интерфейс обязан честно об этом сказать.

Фильтры категорий показываются **только для тех категорий, что рядом реально
есть**. Предлагать «Ледники» там, где ледников нет, — обещание, которое экран
не выполнит. Отдельно учтено: выбор, сделанный в другом городе, не остаётся
висеть невидимым фильтром.

### Карточка места

Текст по цепочке подстановки языков, факты, избранное, кнопка во внешние карты.
Если текста на языке пользователя нет, показывается запасной с честной пометкой.

## Ключевые решения слоя данных

### Цепочка языков

`язык пользователя → en → no → имя из OSM`, реализована через `COALESCE`
в SQL с флагом `is_fallback` (§8.4 спеки). Приложение никогда не показывает
пустой экран.

### Два файла базы

Контентная база поставляется пакетом и открывается только на чтение;
избранное и заметки живут в отдельном файле. Обновление контента не должно
стирать данные пользователя.

На Этапе 1 база одна — разделение через `ATTACH` вводится на Этапе 2, когда
появится реальный пакет. Подключение при этом остаётся одно: это даёт честный
SQL-джойн `places ⋈ favorites` вместо `WHERE id IN (...)` с сотнями значений.

### Профиль как веса

Профиль не фильтр, а множитель: `расстояние / (1 + boost × 0.35)`.
Веса живут в коде, а не в базе — их придётся часто менять по обратной связи,
и ради этого не должен пересобираться контентный пакет.

## Платформы

| Платформа | Подключение к БД | Статус |
|---|---|---|
| Web | `WasmDatabase`, OPFS/IndexedDB | основная площадка разработки |
| Android / iOS | `NativeDatabase`, файл в документах | код есть, не проверено |
| Windows | — | не поддерживается, и не планируется |

Про то, что web проверяет, а что нет — [[development#Где что проверяется]].
