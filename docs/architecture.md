# Архитектура приложения

Как устроен Flutter-клиент. Схема базы — в [[data-model]], подготовка данных —
в [[pipeline-plan]], причины решений — в [[decisions]].

## Общая форма

Приложение почти целиком **read-only поверх локального SQLite**. Мутируемого
состояния мало: избранное, заметки, фильтры, профиль, выбранный язык. Всё
остальное — параметризованные запросы к базе.

Из этого следует выбор инструментов: экран здесь это функция
`(id, язык, фильтры) → запрос`, что ложится на family-провайдеры Riverpod
без событий и состояний в стиле Bloc.

```
Виджет → Riverpod-провайдер → AppDatabase (drift) → SQLite
```

Сети в этой цепочке нет вообще. Единственные сетевые обращения в готовом
продукте — скачивание пакетов контента и открытие внешних карт.

## Структура каталогов

```
app/lib/
├── main.dart              точка входа, темы, локали
├── core/
│   ├── providers.dart     БД, положение, фильтры, выдача
│   ├── settings.dart      язык, город и профиль с сохранением
│   ├── profile.dart       интересы, веса, триггер вопроса
│   ├── categories.dart    категории: подписи, иконки, цвета
│   └── known_places.dart  справочник городов для ручного ввода
├── data/
│   ├── tables.dart        схема drift
│   ├── database.dart      запросы, гаверсинус, азимут
│   ├── connection*.dart   платформенные подключения
│   └── seed_data.dart     тестовые данные Этапа 1
└── features/
    ├── home/              стартовый экран, атрибуция, выбор языка
    ├── nearby/            «Рядом со мной», выбор города
    ├── cities/            обзор страны, города, сетка карточек
    ├── place/             карточка места
    ├── search/            поиск по FTS5
    ├── favorites/         «Моя поездка»
    ├── emergency/         телефоны экстренных служб
    └── profile/           вопрос об интересах
```

## Экраны

### Стартовый

Фотография Гейрангер-фьорда на весь экран и два пути: [[#Рядом со мной]]
и «Куда поехать». Второй нужен там, где первый бесполезен: человек ещё дома
и планирует поездку. Третий, «Моя поездка», появляется только когда в
избранном что-то есть.

Снимок под CC BY-SA, автор подписан внизу экрана — без этого показывать
его нельзя (§7 спеки). Полный список источников — по иконке информации.

### Рядом со мной

Заменяет интерактивную карту ([[decisions#Карта вне MVP]]). Показывает
ближайшие места с расстоянием и стороной света. Работает офлайн полностью.

Положение берётся в порядке: указанный вручную город → GPS → центр страны
с большим радиусом. Последний вариант оставляет экран полезным, когда
положение неизвестно, но интерфейс обязан честно об этом сказать.

Фильтры категорий показываются **только для тех категорий, что рядом реально
есть**. Предлагать «Ледники» там, где ледников нет, — обещание, которое экран
не выполнит. Отдельно учтено: выбор, сделанный в другом городе, не остаётся
висеть невидимым фильтром.

### Карточка места

Фотография с Commons с подписью автора, текст по цепочке подстановки языков,
факты, избранное, кнопка во внешние карты. Если текста на языке пользователя
нет, показывается запасной с честной пометкой.

Внешние приложения открываются напрямую, без `canLaunchUrl` — см.
[[decisions#Внешние приложения открываем напрямую, без canLaunchUrl]].

### Поиск

FTS5 по 66 тысячам объектов, запрос с задержкой 250 мс. Ищет одновременно
по языку интерфейса, норвежскому и английскому: человек набирает то, что
видит на указателе. Пользовательский ввод экранируется перед подстановкой
в синтаксис FTS5.

### Моя поездка

Сохранённые места, разделённые на «хочу посмотреть» и «уже был», заметки,
удаление свайпом. Единственный экран, где данные создаёт сам человек.

### Экстренная помощь

Телефоны служб Норвегии и координаты пользователя для диктовки диспетчеру.
Работает офлайн и без SIM-карты — см. [[decisions#Раздел экстренной помощи]].

## Ключевые решения слоя данных

### Цепочка языков

`язык пользователя → en → no → имя из OSM`, реализована через `COALESCE`
в SQL с флагом `is_fallback` (§8.4 спеки). Приложение никогда не показывает
пустой экран.

### Два файла базы

Контентная база поставляется пакетом и открывается только на чтение;
избранное и заметки живут в отдельном файле. Обновление контента не должно
стирать данные пользователя.

Пока база одна — разделение через `ATTACH` ещё не введено, и обновление
контента сотрёт избранное. Это ближайшая задача. Подключение при этом остаётся одно: это даёт честный
SQL-джойн `places ⋈ favorites` вместо `WHERE id IN (...)` с сотнями значений.

### Профиль как веса

Профиль не фильтр, а множитель: `расстояние / (1 + boost × 0.35)`.
Веса живут в коде, а не в базе — их придётся часто менять по обратной связи,
и ради этого не должен пересобираться контентный пакет.

## Что переживает перезапуск

Сохраняется только то, что человек выбрал сам: язык интерфейса, указанный
вручную город и профиль интересов вместе с отметкой «вопрос уже задавали».
Всё остальное — контент из базы и результаты запросов — пересчитывается
заново.

Хранилище (`shared_preferences`) открывается в `main()` до `runApp` и
подставляется через `overrideWithValue`. Это позволяет провайдерам читать
значения синхронно: иначе первый кадр рисуется с языком по умолчанию,
а следующий — с сохранённым, и на старте видно мигание.

Если язык не выбирали вручную, он каждый раз берётся из системы — то есть
смена языка телефона подхватывается.

## Платформы

| Платформа | Подключение к БД | Статус |
|---|---|---|
| Web | `WasmDatabase`, OPFS/IndexedDB | основная площадка разработки |
| Android | `NativeDatabase`, файл в документах | проверено на устройстве |
| iOS | `NativeDatabase`, файл в документах | код есть, сборок не было |
| Windows | — | не поддерживается, и не планируется |

Про то, что web проверяет, а что нет — [[development#Где что проверяется]].
